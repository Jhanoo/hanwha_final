# 요구사항 명세와 추적

프로젝트 루트 `AGENTS.md`와 커밋 규칙을 따른다. 사용자 요구와 기존 코드를 먼저 읽고, 현재 구현·계획·가정·검증 결과를 구분한다. 이 스킬은 현재 프로젝트를 위해 작성한 로컬 지침이다.

## 작업 순서

1. `docs/prd.md`와 코드를 확인한다. PRD가 없으면 사용자 요구를 출처로 기록하고 제품 결정을 가정으로 구분한다.
2. `docs/requirements.md`에 FR-001(기능), NFR-001(비기능) ID를 부여한다. 기존 ID는 바꾸거나 재사용하지 않는다.
3. 각 요구사항은 한 가지 동작만 포함하고 역할, 입력, 전제, 결과, 예외, 권한, 우선순위를 명시한다.
4. 정상·잘못된 입력·중복·외부 시스템 실패의 수용 기준을 Given/When/Then으로 작성한다.
5. 성능·보안·접근성 요구는 측정 방법과 목표의 출처를 기록한다. 인증 미구현을 완료로 표기하지 않는다.
6. `docs/traceability.md`에서 PRD ID → 요구사항 ID → API/화면/DB → 테스트 → 구현 상태를 연결한다.
7. 누락·충돌·검증 불가능한 표현을 찾아 수정한다. 미정 정보는 질문 또는 가정으로 남긴다.

## 산출물 템플릿

[템플릿](references/template.md)을 필요한 부분만 사용한다. 요청받은 작업을 실행하고 결과를 검증한다. 이 템플릿 자체는 완성된 제품 문서나 실행 결과가 아니다.
