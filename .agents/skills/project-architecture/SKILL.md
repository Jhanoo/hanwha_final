# 아키텍처와 구현 계획

프로젝트 루트 `AGENTS.md`와 커밋 규칙을 따른다. 사용자 요구와 기존 코드를 먼저 읽고, 현재 구현·계획·가정·검증 결과를 구분한다. 이 스킬은 현재 프로젝트를 위해 작성한 로컬 지침이다.

## 작업 순서

1. 요구사항과 기존 구조를 읽는다. 현재 SQLite를 기준선으로 삼고 목표 MVP DB는 PostgreSQL + pgvector로 설계한다.
2. `docs/architecture.md`에 UI, 상담 Agent, 지식 검색, TicketAdapter, DB, 외부 서비스의 책임과 경계를 적는다.
3. Mermaid로 요청 및 데이터 흐름을 표현하고, 로컬 데모와 계획된 운영 구조를 분리한다.
4. LLM과 규칙 모드, 로컬 티켓과 외부 티켓의 인터페이스를 정한다. 외부 장애 시 오류, 재시도, 중복 방지 방침을 적는다.
5. 중요한 선택은 `docs/adr/`에 대안·근거·영향·상태를 기록한다. 불필요한 프레임워크를 도입하지 않는다.
6. `docs/implementation-plan.md`에 요구사항 ID, 작업 순서, 의존성, 완료 기준과 검증을 연결한다.
7. 코드 변경까지 요청받은 경우 계획에 이어 구현한다. 문서 작성 자체가 실행 결과를 보장한다고 표현하지 않는다.

## 산출물 템플릿

[템플릿](references/template.md)을 필요한 부분만 사용한다. 요청받은 작업을 실행하고 결과를 검증한다. 이 템플릿 자체는 완성된 제품 문서나 실행 결과가 아니다.
