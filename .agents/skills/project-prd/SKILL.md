# 제품 기획과 PRD 작성

프로젝트 루트 `AGENTS.md`와 커밋 규칙을 따른다. 사용자 요구와 기존 코드를 먼저 읽고, 현재 구현·계획·가정·검증 결과를 구분한다. 이 스킬은 현재 프로젝트를 위해 작성한 로컬 지침이다.

## 작업 순서

1. README와 현재 코드, 사용자 요구를 읽고 구현된 기능과 계획 기능을 구분한다.
2. 기본 목표는 직원 IT 상담 → 해결 안내 → 미해결 티켓 접수 → 담당자 처리다. 직원, IT 담당자, 관리자의 목표를 나눈다.
3. 아래 템플릿을 바탕으로 `docs/prd.md`를 작성한다. 기존 문서는 갱신하며 사용자 결정을 보존한다.
4. 필수 질문만 묻고 나머지는 가정으로 표시한다. 정해지지 않은 일정, 예산, 실측 지표를 만들지 않는다.
5. 각 MVP 기능에 PRD-001 형태 ID를 붙이고 완료 기준을 관찰 가능한 동작으로 적는다.
6. 문서에서 기능 범위, 사용자 흐름, 성공 지표가 일치하는지 검토한다. 요구사항 작성은 `project-requirements`로 이어간다.

## 산출물 템플릿

[템플릿](references/template.md)을 필요한 부분만 사용한다. 요청받은 작업을 실행하고 결과를 검증한다. 이 템플릿 자체는 완성된 제품 문서나 실행 결과가 아니다.
